# Step 10: Making it feel good to use (UX)

- **UX vs UI:** UI is how it looks; UX is how it feels to use. Fewer clicks, instant feedback, and no way to lose work are UX.
- **Autosave with debounce:** wait until the coach stops typing for 600 ms, then save once, instead of once per key press. The badge shows Saving… / ✓ Saved.
- **Derived state:** the save status isn't stored. It's worked out every redraw from "what the rows say" vs "what the server last confirmed". Less state means fewer bugs.
- **Flush on unmount:** an effect's cleanup runs when the page closes. If a save is still waiting, it's sent then, so leaving the page never loses changes.
- **Drag and drop (dnd-kit):** `useSortable` gives each row drag handlers. It works with a mouse, touch, and the keyboard (Space, arrows, Space).
- **Optimistic UI:** the list changes on screen right away, and saving happens in the background.
- **Modal (`<dialog>`):** a pop-up window. The browser's built-in one handles the Escape key and focus for free.
- **Toast + Undo:** a short message after an action. Undo is friendlier than "Are you sure?" for things that are easy to reverse, like archiving.
- **Context (`createContext` / `useContext`):** share one thing (the `showToast` function) with every component without passing it down by hand.
- **Design tokens:** colors, radius, and shadows as CSS variables in one place, so the whole look can change from one block.
- **N+1 queries:** loading a list, then one extra query per item. `selectinload` loads all the slots in one go.
